DDPS 平台交付件 —— Python 参照 + C++ 复刻（单种子口径）

数据驱动物理代理（Data-Driven Physical Surrogate）在线调优 · 56 GBd PAM4 · 全物理链路 · 单仿真种子 42

1. 系统现状

平台以两套实现交付同一套算法与物理模型，互为校验、共用同一配置口径与同一套冻结模型：

实现角色入口 / 产物
Python原理参照（快速验证算法、物理层、调优逻辑）main.py、test_generalization.py 等 *.py
C++17一比一复刻，用于大规模仿真与在线调优cpp/src/*.hpp + cpp/main.cpp → run_ddps.exe

物理链路（两实现一致）：Tx PAM4（±3/±1，峰值 3）→ 2sps 成型 + 5 抽头 Tx FFE → DAC ZOH 2→8sps + 量化噪声 → Tx 前端（S4P 插损 + 主噪声 + Tx CTLE 2Z3P + driver 增益 + driver 带宽）→ MZM 电光非线性 → 光纤（损耗 + 色散）→ PIN 平方律 + DGD + 散弹/热噪声 → TIA（AGC 目标 RMS=√5）→ Rx 插损 + 主噪声 + Rx CTLE → ADC → Rx DSP（两相相关同步 → 22 抽头 LMS FFE → Burg AR 白化 → 4 态 Viterbi MLSE）→ 逐位 Gray BER。

在线调优搜索空间：7 维 = [4 个 FFE 旁瓣, gDC, gDC2, u_gain]；gain = 0.3399 × 10u_gain。Model A（8 维发端探针 = 7 抽头 Tx FIR + drive_rms）给出下降方向；Model B（7 维参数域）做相对风险否决。每步 7 维中心差分 = 14 个 ±ε 微扰态，每个微扰态的端到端 BER 也一并记录（记账、不参与方向）。

218 单种子的分辨率语义：真实 BER 到 step 3 已落入 0 错误地板（9.919e-07），此后 3~15 步真实 BER 无法再区分，因此本口径下「最优步」= 首次触地的 step 3。下降路径本身与更细口径（222 × 3 种子）完全一致——step 4 的 gDC=6.864、gain=0.1334 正是更细口径下的最优工作点。这是单种子、短块长交付口径的固有分辨率，而非算法差异。

6. 统一入口

Python 与 C++ 均由同一套配置口径驱动；后端、点数、噪声、种子全部可配：

# C++ 后端：全量在线调优（Base_IL10x10，2^18 符号，无噪声，单种子 42，次优起点）
.\cpp\build\run_ddps.exe cpp\config.txt --num-symbols 262144 --tx-noise-snr 0 \
    --seed 42 --n-steps 15 --seed-config result\seed_config_bad_1e4.json

# 快速验证：低 SNR 人为噪声 + 少点数（发端 DSP 出口 SNR=23 dB、2^14 符号）
.\cpp\build\run_ddps.exe cpp\config.txt --num-symbols 16384 --tx-noise-snr 23 --seed 42

# 构建（动态链接，见 cpp/build.ps1）
powershell -File cpp\build.ps1

开关语义：--num-symbols 仿真符号数；--tx-noise-snr 发端人为加噪 SNR(dB)，0 = 关闭（真实链路噪声）；--seed 系统种子（默认 42）；--seed-config 次优起点 JSON；--n-steps 最大步数。Python 侧同一套开关见 test_generalization.py。

7. 交付口径

  • 单种子：一次交付 = 一个种子（42）。不用多种子平均；种子切换是用户复现时的动作。
  • 冻结模型复用：在线调优直接加载 models/ddps/ 的固化 A/B 代理，不重训、不重采样。
  • 两平台同源：C++ 与 Python 读同一配置、同一模型转换产物，数值等价。
