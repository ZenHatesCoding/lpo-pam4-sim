# DDPS 方法

## 1. 架构

DDPS：链路口径（5-tap FFE、Tx CTLE 为 OIF 2Z3P peaking 拓扑、Rx CTLE 固定 `gDC=6/gDC2=3`、Tx 路径无 VGA/无 RMS 归一化，Rx 侧 TIA 一层物理 AGC）。在线方向只由一个代理提供：

- **Model A（方向代理，唯一在线代理）**：输入 = [7-tap Tx FIR 探针, drive_rms]（8 维波形域）→ `log10(BER_MLSE)` 条件均值。在线拿不到收端 BER，只能拿发端探针，所以 A 的全部意义就是建立「发端探针 → 收端 BER」的方向映射。WhiteBoxRidge（二阶多项式 + L2 Ridge 闭式解，带解析梯度）。
- **参数域产物（Stage-1 离线产物）**：输入 = [4 FFE 旁瓣, gDC, gDC2, drive_rms]（7 维参数域）→ `log10(BER_MLSE)` 保守上包络。它随 Stage-1 一起训练并导出（`models/ddps/model_b.json`），**不在线使用**：在线搜索不做候选否决、没有红线、没有轨迹信任域。

Stage-1 与 Stage-2 的参数口径必须分清：

| 阶段 | 自变量 | 抽头口径 |
| --- | --- | --- |
| Stage 1（数据集采样，离线冻结） | 4 个旁瓣 + gDC + gDC2 + u_gain（7 维 LHS，仅数据集自变量） | 主抽头由归一化恒等式 `1 − Σ|旁瓣|` 派生（`construct_taps()`，受 `PEAK_SUM_LIMIT=0.8` 约束），只用于构型与评估 |
| Stage 2（在线搜索） | 5 个抽头 + gDC + gDC2 + u_gain（8 维） | 5 个抽头全部自由、地位相同、无边界；无派生、无峰值和约束 |

## 2. 在线搜索空间（8 维）

`x = [t0, t1, t2, t3, t4, gDC, gDC2, u_gain]`，`N_DIM = 8`、`N_TAP = 5`、`N_SHAPE = 7`。

- 5 个 Tx FFE 抽头全部是自由搜索变量，**没有任何边界**（没有 `FFE_TAP_MIN/MAX`、没有 `PEAK_SUM_LIMIT`、没有抽头信任盒）。两平台的投影实现：Python `_search_bounds()` 在抽头维返回 `±inf`，C++ `bounds()` 在抽头维用 `INF_BOUND = 1e300` 这个有限大数代替 `±inf`（便于写 `min/max`）；两者对抽头都是**不生效的投影**，只有下面三个物理量程会真正截断。
- 只有物理量程保留：`gDC ∈ [0, 12] dB`、`gDC2 ∈ [0, 4] dB`、`u_gain ∈ [−0.52, 0.6]`（`u_gain = log10(gain / 0.3399)`，标称 `DRIVER_GAIN_NOMINAL = 0.3399`）。
- 步长尺度（**不是参数范围**）：`STEP_SPAN = [0.20]×5 + [6.0, 6.0, 0.60]`，来自 `TRUST_FFE=0.10`、`TRUST_CTLE=3.0`、`GAIN_TRUST=0.30`。
- 步长调度：`α_k = 0.05 × 0.97^k`；更新 `x_{k+1} = clip(x_k − α_k · span ⊙ d, 物理量程)`。方向 `d` 由三组（FFE / CTLE / gain）各自单位化得到；某组范数低于 `GROUP_GATE = 1e-3` 就冻结该组。
- **固定 15 步（`n_steps = 15`），代理档不做提前停止。**

为什么抽头不给边界：次优起点在抽头方向本来就不是好点，盒子会把可用范围截成单侧半宽（实测 15/15 用例的最低抽头都被钉在盒壁上、只能单向移动）。步长尺度由 `STEP_SPAN` 单独承担，与「能走到哪里」无关。

## 3. 梯度来源

在线梯度被拆成**两个正交的选择**，合起来是一张 3×2 的矩阵——用哪一格是工程取舍（代价看第 4 节、效果看第 7 节），不是能力边界：

| 维度 | 选项 | 由谁选 |
| --- | --- | --- |
| **形状 7 维怎么拿到斜率** | `full` 每步全量中心差分 / `rotate` 每步轮转 2 维 / `secant` 仅第 0 步后 Broyden 外推 | `--grad-mode` |
| **梯度来自哪里** | `proxy`（发端探针 → Model A 代理，无需回传通道）/ `direct`（收端真实 BER 直接差分，需回传通道） | `--method` |

两行各有 3 种形状维取法，所以是 6 格。`proxy` 行的 gain 维另有解析梯度（3.1）；`direct` 行没有代理可用，gain 维只能实测。

### 3.1 gain 维（第 8 维）：解析梯度，0 微扰

Model A 的 8 维探针 = [绝对标定 7-tap Tx FIR, drive_rms]，driver_gain 是 Tx 链末尾的标量乘子，所以 8 个特征都严格 ∝ gain。gain = g₀·10^u ⇒ `∂feat_j/∂u = ln(10)·feat_j`，于是

```
∂A/∂u_gain = ln(10) · Σ_j (∂A/∂feat_j) · feat_j
```

`∂A/∂feat_j` 由 WhiteBoxRidge 的解析多项式梯度给出（输入标准化后 ÷sd 换算回原始量纲）。每步用**当前落点探针**现算，0 微扰态、永不陈旧。

### 3.2 形状 7 维（5 抽头 + gDC + gDC2）：三种取法一键切换

`--grad-mode full|rotate|secant`：

| 取法 | 机制 | 每步 `±ε 微扰态` | 每用例真实评估（与符号数无关） |
| --- | --- | --- | --- |
| `full` | 每步对全部 7 个形状维做中心差分 | 14 | 225（15 落点 + 210 微扰） |
| `rotate` | 第 0 步全量测一轮，此后每步只重算 `ROTATE_K=2` 个维（`refreshed = [(step·2 + j) mod 7]`），其余维沿用上次实测值；4 步就把 7 个维各刷新一遍、此后循环 | 4 | 85（15 + 70） |
| `secant` | 只在第 0 步测一轮，此后 Broyden 秩一修正 `g ← g + [(ΔA − gᵀs)/‖s‖²]·s`（割线方程剔除 gain 的已知贡献） | 0 | 29（15 + 14） |

- 三种取法的**第 0 步完全一致**：7 个形状维各做一组 ±ε 中心差分 = 14 个微扰态，gain 维走解析。
- 三种取法共用同一次优起点、同一组归一化步长、同一组门控、同一固定 15 步，所以落点与在线代价可以直接比较。
- 中心差分步长 `EPS_VEC = [0.01]×5 + [0.1, 0.1] + [0.05]`（抽头 / CTLE dB / gain dex）。
- 链式法则：`∂BER/∂param_i = Σ_j (∂A/∂probe_j) × (∂probe_j/∂param_i)`；形状维的 `∂A` 由 ±ε 扰动重算探针后查 A 得到。
- 实现：Python `_stage2_descent_proxy(grad_mode=…)`，C++ `stage2_descent_proxy(…, grad_mode, rotate_k, …)`。

**为什么 gain 维不用割线**：Broyden 秩一更新只沿已走过方向修正；gain 维单步位移小、方向分量弱，会被压塌（纯割线实测 gain 维卡在 ×0.302、`u_gain=−0.52` 不动，梯度幅值跌破门控被冻结，而形状维在同样操作下正常收敛）。gain 维改用解析梯度后正常爬升。

### 3.3 方向能不能拐：组内方向偏离的实测与秩一修正的锁死性

`trace_<用例>.csv` 的 `grad` 列记下了每步实际使用的 8 维梯度。把 5 个抽头维单独取出来，量一下「第 k 步梯度」与「第 0 步梯度」的夹角，就能回答「方向会不会拐」：

| 格 | 抽头梯度 vs 第 0 步（均值 / 最大） | 相邻步之间 | CTLE 2 维 vs 第 0 步 | 抽头方向是否被重估 |
| --- | --- | --- | --- | --- |
| `full` | 10.0° / 33.3° | 1.6° | 13.1° |
| `rotate` | 8.7° / 27.0° | 2.2° | 13.2° |
| `secant` | **0.0° / 0.0°** | **0.0°** | **49.9°** |
| 回传 × full | 17.1° / 52.2° | 11.2° | 21.7° |
| 回传 × rotate | 14.5° / 63.2° | 8.2° | 23.2° |
| 回传 × secant | **0.0° / 0.0°** | **0.0°** | **52.0°** |

- 数字来自 2^22 全量结果（六格，各 15 用例）的 `trace_*.csv`，由 `tools/turn_angle_table.py --prefix result/ddps_cpp` 实算：`grad` 列 → 抽头 5 维子向量 → 夹角；口径与交付件 §4.2.3 的表完全一致（把全部「用例 × 步」的夹角汇总后再取均值 / 全局最大，不是先按用例平均）。换取法或换规模后重跑即可。
- **走 `secant` 的两格（代理 secant 与回传 × secant）的 0.0° 是结构性的，不是巧合**：秩一修正项 `[(ΔA − gᵀs)/‖s‖²]·s` 只沿位移方向 `s` 叠加，而各组步长尺度在组内相等（抽头 0.20、CTLE 6.0 dB），组归一化后 `s` 在组内与梯度同向，所以组内梯度**正交于 `s` 的分量永远不变**——抽头方向被锁死在初始射线上，只能沿它前进或后退。
- **重新施加微扰的两格，方向确实会拐**：回传行实测抽头方向平均偏离初始射线 17.1°（`full`）/ 14.5°（`rotate`），相邻步之间 11.2° / 8.2°；代理行同口径只有 10.0° / 8.7° 与 1.6° / 2.2°。真实 BER 的差分梯度幅值更大也更抖，方向能拐、落点也更跳——交付件 6.5 里回传 × full 落后现役的两例就来自这种抖动。

**CTLE 2D 那一列的绝对值不可当真**：梯度接近零时夹角没有意义，而 CTLE 维在代理行有 38% 的落地步贴在物理量程上（`gDC2` 撞 0 下界），那 49.9° / 52.0° 主要是边界与近零向量造成的，不能读成「secant 在 CTLE 上学会了转向」。要看“到底有没有拐”，用**路径共线度**（总位移里沿第 0 步方向的分量占比，步长尺度归一化后计算）更稳：

| 格 | 整体共线度 | 抽头 5 维共线度 | CTLE 贴物理量程的落地步占比 |
| --- | --- | --- | --- |
| `full` | 0.924 | 0.988 | 40.2% |
| `rotate` | 0.936 | 0.992 | 39.8% |
| `secant` | 0.343 | **1.000** | 37.6% |
| 回传 × full | 0.947 | 0.979 | 0.0% |
| 回传 × rotate | 0.951 | 0.979 | 0.0% |
| 回传 × secant | 0.999 | **1.000** | 0.0% |

- 抽头 5 维：两格 `secant` 都是 **1.000**（一步都没转过），`full` / `rotate` 是 0.988 / 0.992——确实在转，但转得很小。
- 整体：`full` / `rotate` / 回传行都在 0.92~0.95，说明**即使每步重测，绝大部分位移仍沿第 0 步方向**，即这个起点附近的最优路接近一条沟。
- 回传 × secant 0.999（标准直线，一次没贴界），代理 × secant 只有 0.343：不是它在转向，而是 CTLE 撞量程后被 `clip` 掉的位移让轨迹看起来在摆。
- 结论：`secant` 能用不是因为它够聪明，而是**这个起点在「正确的沟」上**（幅度错了、结构没错），第 0 步的全维差分已经指对了方向；它输了 2.71 倍的那一例（`HighNoise_IL10x10`）正是初始方向不对、又没机会纠正的情形。
- 复现：`python tools/path_collinearity.py --prefix result/ddps_cpp`（逐格 / 逐用例两种口径都有输出）。



## 4. 真实评估代价（不可省的物理口径）

**真实评估 = 真的把参数打到链路上。** 探针不是算出来的：要读到探针，就必须把当前参数写进链路、跑一遍 Tx 前端；要拿到真实 BER，就必须跑完整条链路加 MLSE。每个落点、每个 `±ε 微扰态` 都是链路真实经过的工作点。

- 记账口径：`n_real_evals = n_landed + n_probe_states`，逐用例写进 `case_summary.csv`；微扰态明细写进 `probes_<用例>.csv`（step / param / sign / 坐标 / 真实 BER）。
- 单次评估实测：C++ 2^18 1.86 s、C++ 2^22 **36.6 s**（15 用例 15 步全量实测均值 `elapsed_sec / n_real_evals`；单进程阶段性峰值 RSS ≈5.6 GB）。
- 同一 2^18 规模下 Python 与 C++ 的实测对比：Python ≈6.8 s/次、C++ ≈1.89 s/次（各取结果目录里 `elapsed_sec / n_real_evals` 的实测均值），即 Python 慢 ≈3.6 倍；按符号数线性外推到 2^22，Python 单次评估 ≈110 s，一个 15 用例的 `full` 档要跑 ≈4 天，而 C++ ≈8.6 小时（15 用例 × 225 次 / 4 路并行 × 36.6 s）。这就是大点数全量仿真只走 C++、Python 只承担 2^18 原理验证的现实原因。
- 所以各格的差别不是"精度微调"，而是实打实的在线代价差：代理行每用例 `full` 225 次真实评估、`rotate` 85 次、`secant` 29 次；回传行机制相同，只是把梯度换成实测真实 BER（第 0 步 16 态，此后每步 16 / 4 / 0 态，落地仍是 15 次）。
- 2^22 全量 15 用例用 `--jobs 4`（WSL 放开到 28 GB / 20 CPU）。

## 5. 另一条梯度来源：真实 BER 回传（三格）

现役方案假设**没有回传通道**（在线拿不到收端端到端 BER，只能靠发端探针训练方向代理）。这一节是同一张矩阵的第二行——把梯度来源换成真实 BER 回传：

- 目标 = 真实 `log10(BER_MLSE)`。
- 第 0 步全 8 维中心差分 = 16 个 `±ε 微扰态`（每个微扰态都实测真实 BER；无代理，就没有解析 gain 梯度可用）。
- 此后按 `--grad-mode` 选取法：`full` 每步全 8 维重测（16 态/步）、`rotate` 每步轮转 2 维（4 态/步，`(step·2+j) mod 8`）、`secant` 只走 Broyden 秩一（0 态/步）。
- 保留边际停止（`MIN_GAIN_DEX = 0.01` dex，step > 0 才判）：目标到 0 错误检测限后梯度信号消失，停下是目标本身的属性。
- 与代理行三格共用同一 8 维搜索空间 / 步长调度 / 组门控 / 15 步上限。差别只有两处：目标（真实 BER vs 代理预测）与梯度来源（实测中心差分 vs 探针链式 + 解析 gain）。
- 实现：Python `_grad_direct_chain` / `_stage2_descent_direct`；C++ `grad_direct_chain` / `stage2_descent_direct`；CLI `--method direct --grad-mode full|rotate|secant`。2^22 结果目录 `result/ddps_cpp_direct_{full,rotate,secant}/`（secant 目录沿用最早那批 direct 全量数据，已用新代码 2^18 逐位核对一致）；2^18 等价目录 `result/ddps_equiv_{py,cpp}_direct_<取法>/`。
- 非抽头维必须用**扰动后的坐标**取探针（`gdc_p = xp[N_TAP]`、`gdc2_p = xp[N_TAP+1]`、`gain_p = gain_from_u(xp[N_TAP+2])`），否则 gDC/gDC2 两维梯度恒为 0、两平台不一致。

## 6b. 起点鲁棒性对照（换起点重跑）

六格之间的强弱如果只在某一个起点成立，那套比较就没有意义。这一节把起点本身当成实验变量：

- **起点怎么坏**：三个差起点，都在基线用例 `Base_IL10x10` 上校准到 9.8e-04（原起点 1.3e-04，差 7.7 倍），
  但坏法不同——纯幅度错（形状与 CTLE 不动、驱动增益再压低 2.6 dB）、纯均衡错（增益不动、Tx CTLE 的
  peaking 与低频 shelf 拉偏）、形状+幅度都错（4 个 FFE 旁瓣放大 3 倍、增益再降 0.8 dB）。
  起点 BER 一律由链路真实评估得到（`tools/probe_start_point.py`，1 步 × 2^18），不做模型外推。
- **怎么跑**：`tools/run_seed_study.py`，3 起点 × 6 格 = 18 次跑批，2^21 符号/点、15 用例、单种子 42、固定 15 步；
  与现役 2^22 六格共用同一 8 维空间 / 步长调度 / 组门控 / 取法矩阵，差别只有起点与规模。
  18 格实跑 30 h 56 min（`ALL DONE wall=111403s fails=none`）。
- **怎么读**：倍率 = 该格落点 / 同一起点下 `代理 × full` 的落点，逐用例算完再取几何均值；
  看每一格在三个差起点下的倍率是否同档。同档 = 强弱不是起点凑出来的。现役起点是另一规模（2^22），
  只当锚点看绝对落点，不参与这个判断。
- **先看噪声带再下判词**：2^21 下多数用例在 15 步内已经落到检测底（每 419 万 bit 错 0 个），
  剩下少数用例才承载信息量。把 15 个用例 bootstrap 重采样，倍率的 90% 区间中位半宽约 ±64%——
  比这个带小的差别（例如 1.16× 与 1.00×）不能读成真实差距。
- **起点必须可核对**：每个用例的 `run.log` 里有 `[seed] src=… taps=… gdc=… gdc2=… u_gain=…`，是 C++ 实际生效的起点。换起点后先核对这一行再看结果——路径写错时 C++ 会静默退回内置默认起点，那是个近似标称的好点，会让整批结果看起来「零误码」。
- 结果目录 `result/seed_study/<起点>/ddps_cpp_<格>/`（结构同现役格，`verify_ddps.py --prefix` 可直接验收，
  加 `--skip-equivalence --expect-symbols 2097152`）。

### 6b.2 换起点改的是什么

**第一层：族内顺序不随起点变。** 回传三格在三个差起点下的内部顺序完全一致——`回传 × full` ＞
`回传 × rotate` ＞ `回传 × secant`（从好到差），只是幅度随起点变（0.78~1.16× → 1.24~1.84× →
1.77~6.19×）。代理三格之间基本打平：`代理 × rotate` 1.000~1.046×、`代理 × secant` 0.960~1.91×。

唯一明显不齐的是 `代理 × secant` 在纯幅度错起点上的 1.91×。它第 0 步把各组之间的比例一起定死，
之后 gain 每走一格、CTLE 就按固定比例跟着走一格：CTLE 本来就对的时候这个"跟着走"是有害的
（该起点最难用例上 gDC 比 `代理 × full` 低 1.84 dB、BER 差 30.20 倍），CTLE 本来就错的时候无害
（纯均衡错起点上 gDC 高 0.84 dB、BER 反而是 0.80×）。所以这一格的强弱取决于起点把误差落在哪一组，
不是方向估计准不准。

**第二层：族间差不随"取法"变，随"代理还能不能信"变。** 起点还在代理邻域里时两族打平——
纯幅度错 `回传 × full` 0.78×、纯均衡错 1.16×，两者都在 ±64% 的噪声带内；几何均值被大量已经打平的
用例摊薄，逐用例的差别集中在少数难用例上。形状+幅度都错这个起点上代理才真的失效：代理三格
45/45 个用例的最好落点停在第 0 步（15 步走完没有一步更好，而第 0 步本身已经比起点差），
代理预测（`pred_a`）一路变好 8.31×、实测反而变差 0.62×，末步几何均值比起点差 6 倍；
同一批用例上 `回传 × full` 把落点压到 7.25e-06（相对代理 0.0009×，好 1109 倍），
但仍明显高于另外两个起点的 2.3~6.4e-07——那一片不在代理的训练邻域里。

一句话读法：换起点**不改**"族内哪种取法更好"（全量重测 ＞ 轮转 ＞ 只在第 0 步测一次），
**改的是**"代理还能不能用"：起点还在邻域内时代理免费且够用，出了邻域只有回传通道能把落点拉回来。
后一层要按第 8 节的有效范围判断起点落在哪里。

## 8. 已知边界

1. 强信号用例最优 BER 低于 2^22 点估计分辨率：0 错误时 `calculate_ber` 按 `0.5/(2·min_len)` 报告（≈6.0e-8），单种子 42 的 95% CL 上界为 `3/N_bits`（N_bits ≈ 8.37e6，≈3.6e-7），只能给上界而非点估计。
2. per-case target_rms 是离线标定的，换器件需重跑扫描（≈20 min）。
3. 代理是局部模型；在线只靠梯度组门控 + 物理量程投影约束，**没有代理否决层、没有红线**。落点是否变差由实测 BER 事后核验，并在交付件逐条列出。
   **有效范围要按实测说**：把 FFE 旁瓣放大 3 倍当起点（6b 的第三个差起点）时，代理三格 15 个用例
   **全部**的最好落点停在第 0 步、`pred_a` 预测变好 8.31× 而实测变差 1.62×——代理看不见自己失效。
   有回传通道时用真实 BER 复核一次落点（比起点差就退回起点）或干脆改用回传格（同批用例上
   `回传 × full` 落到代理的 0.0013×）；没有回传通道时唯一能做的是**部署前把起点校回训练邻域内**
   （数据集覆盖范围就是邻域边界），并如实标注这个前提。
4. 方向代理的绝对标定弱（只用于方向），步长由各维步长尺度决定。
5. 等价性只在 2^18 小点数低 SNR 下比对（唯一允许的比对口径）；2^22 全量只用 C++ 跑。
6. 真实 BER 回传行需要收端回传通道；2^22 规模下每读一次真实 BER 就要跑完整条链路（≈36.6 s/次），这是它相对代理行的全部代价来源。
