## 1. 链路口径：没有 VGA、没有 RMS 固定

```
PAM4 → 9-tap Tx FFE → DAC(ZOH, ENOB 5.5) → Tx 电插损(S4P, Tx IL) → +1 mV 前端噪声
     → Tx 模拟 CTLE(gDC,gDC2) → Driver(真实增益 g) → Driver 带限(40 GHz) → MZM
     → 光纤(CD/DGD) → PIN → TIA → Rx 电插损(S4P, Rx IL) → ADC → Rx FFE(22-tap,LMS)
     → Burg 白化 → Viterbi MLSE(memory=1) → BER_MLSE
```

要点：

1. **入 MZM 的摆幅 = 前端电平 × driver_gain**，由物理自然决定。
   v3 曾在 CTLE 后插入 VGA 做固定 RMS 归一化，这会削弱甚至抵消增益的作用；v4 全部删除。
   下游只有 TIA/ADC 的数字 AGC（它把整体电平归一化，但不改变"信号/噪声"之比，
   因此不会把增益的作用抹掉）。
2. **标定**：`tools/calibrate_driver_gain.py` 实测给出 `DRIVER_GAIN_NOMINAL = 0.4381`，
   使**基线环境（Tx/Rx IL = 10 dB）+ 种子 FFE/CTLE** 下 MZM 摆幅恰好 = `driver_vpp = 0.617 Vpp`
   （延续 SJTU 口径）。该绝对值小于 1 只是本仿真器 DAC 满量程约定较大所致；
   对外统一按**倍率** `g / DRIVER_GAIN_NOMINAL` 表述。
3. **增益搜索箱 = ×0.30 ～ ×4.00**（对应 MZM 摆幅 0.19～2.46 Vpp）。
   这个范围覆盖了"10 dB → 20 dB 插损需要约 3 倍补偿增益"的需求，同时包含欠驱动与过驱动两侧，
   让优化器自己找折中。参数化用 `u = log10(g / g0)`，让步长与增益量级无关。
4. `create_config.py` 的默认 `driver_gain` 与该标定值保持一致（0.4381）。

## 2. 三组自由度（11 维）

| 组 | 维度 | 物理含义 | 边界 | 种子 |
| --- | --- | --- | --- | --- |
| ① FFE | 8 | 8 个旁瓣（主抽头 = `1 − Σ|旁瓣|` 派生） | ±0.30，Σ\|旁瓣\| ≤ 0.8 ⇒ 主抽头 ≥ 0.2 | `[0,0,−0.034,−0.2987,·,0,0.0582,0,0]` |
| ② CTLE | 2 | post-channel 双级直流增益（频谱整形） | [−5, +5] dB | 0 dB / 0 dB |
| ③ Driver 增益 | 1 | 入 MZM 摆幅（OMA vs MZM 线性度） | 倍率 ×0.30～×4.00（对数） | ×1.00（标定值） |

搜索向量 `x ∈ R¹¹ = [8 旁瓣, gDC, gDC2, u_gain]`；在线搜索盒 = FFE ±0.10、CTLE ±3 dB、增益走满整箱。
**三组自由度都由同一条梯度下降直接求解**，没有"某一组只做扫描/只做兜底"的特殊处理。

读法：**增益不是越大越好** —— 摆幅超过约 0.6 Vpp 后 MZM 非线性迅速吃掉全部收益（×2.0 就劣化 100 倍），
所以最优增益有一个内部最优点（本用例在 ×0.5～×0.65）；而高插损场景需要更大增益。
**这正是它必须可调、且必须与 FFE/CTLE 联合求解的原因。**

## 3. 双代理（AB）如何适配"三组自由度都可微"

### 3.1 为什么 A/B 都用**搜索向量 x** 作为输入

x 就是优化器真正要动的 11 个量。用它当输入有三个直接好处：

1. **三组自由度同量纲**：∇ₓ 的 11 个分量天然可比，不会出现"某一组因为特征量纲不同而被别人吃掉"；
2. **没有中间层损失**：FFE 改形状、CTLE 改频响、增益改幅度，全部显式出现在输入里；
3. **可审计**：模型预测与搜索变量一一对应，报告里能逐轴对照实测梯度（见 §3.4）。

v4 第一轮曾把 Model A 的输入做成"Tx 端绝对标定 7-tap FIR 探针"，本轮改成直接用 x，原因是实测证据：

| 输入特征 | 二阶多项式 Ridge（留出集 R²） | RBF 核岭（留出集 R²） |
| --- | --- | --- |
| Tx 端 7-tap 绝对 FIR（探针） | 0.29 | 0.61 |
| **搜索向量 x（11 维，采用）** | **0.56** | **0.62** |

探针是**线性冲激响应**，而真实链路在整形级之前还有 `DAC ENOB = 5.5` 量化这类幅度相关非线性，
探针与真实链路并不严格等价；且 7 抽头绝对 FIR 对 11 维配置是**多对一**压缩。表格同时说明：
波形特征在核方法下也能追平 0.61，即"探针丢信息"不是唯一原因，**二阶基的表达能力**同样是瓶颈。
用 x 的额外好处是：同样精度下参数更少、梯度直接落在搜索变量上，因此本轮采用 x。

### 3.2 Model A（指路）：log10 BER 的条件均值

- 学习器：**白盒 RBF 核岭回归（闭式解，纯 NumPy）**，
  `f(x) = ȳ + k(x)ᵀ(K + αI)⁻¹(y − ȳ)`；
- 输入先按训练集均值/标准差标准化；核宽取**中位距离启发式** `γ = 1/median(‖z_i−z_j‖²)`（只看输入分布、不看标签）；
  `α` 由训练集内 **5 折 CV** 选取（最终 `γ = 0.0468`、`α = 0.1`）；
- 提供**解析梯度** `∂f/∂x`，Stage 2 直接使用，不做有限差分（自检：解析 vs 有限差分最大相对偏差 `1.6e-3`）。

### 3.3 Model B（拦截）：log10 BER 的**保守上包络**，按**变差百分比**判

- 结构：`B(x) = A(x) + c · S(x)`，其中 `S` 是对残差 `|y − A(x)|` 再做一次核岭回归得到的**残差尺度**，
  `c` 标定到测试集覆盖率 ≈ 0.85（本模型 `c = 2.0`，覆盖率 0.91）；
- 拦截线：`allowed_ber = 10^B(x₀) × (1 + MAX_DEGRADE_FRAC)`，`MAX_DEGRADE_FRAC = 0.25`；
- **为什么用百分比**：代理的绝对标定不可信，但"相对种子变差多少倍"是可比的；百分比阈值与 BER 量级、
  环境漂移都无关，跨用例跨环境无需重标定（这是甲方明确要求的口径）；
- **为什么 B 要"保守"**：A 与 B 职责不同 —— A 要**准**（平滑、可导、三组同权），B 要**守**（宁可误拦不可放过）。
  因此 B 的 R²（留出集）天然不为正，这是上包络的定义决定的；拦截只用 B 的**相对变化**，不用其绝对值。

### 3.4 模型验证：全局指标 + **局部方向**实测

留出集（20%）指标由 `models/ddps_v4/meta.json` 给出：

| 模型 | R² | MSE | Spearman | 说明 |
| --- | --- | --- | --- | --- |
| Model A（均值） | 0.623 | 0.251 | 0.830 | 预测水平与排序 |
| Model B（上包络） | −0.073 | 0.715 | 0.697 | 覆盖率 0.91（保守性指标） |

但"空口 R²"不足以判断方向对不对。因此交付件里另给一份**离线实测标定**
（`tools/validate_local_gradient.py`，不参与训练）：在真实链路上对种子工作点沿 11 个搜索轴做中心差分
（262144 符号 × 3 种子 = 22 次独立真实 BER 评估），得到真实 log10 BER 的局部斜率，再与 Model A 的解析梯度逐轴对照：

- **方向命中率 0.82**，按 |实测斜率| 加权 **0.93**，量级相关系数 **+0.70**；
- 全表在 `result/ddps_v4_local_gradient.csv`（报告 §"模型方向验证"会原样列出）。

此外每个用例还有"种子邻域云校验"（8 点 LHS，离线证据、不参与决策），给出逐用例的
Model A/B 方向一致率与局部 Spearman。

## 4. 在线寻优（Stage 2）

1. 拦截线 `allowed_ber = 10^B(x₀) × 1.25`（百分比口径）。
2. **解析梯度** `g = ∇ₓ ModelA(x)`。
3. **分组归一化步长**：把 11 维分成 FFE(8) / CTLE(2) / 增益(1) 三组，**组内**把梯度方向归一化，
   再乘该组自己的箱宽（FFE 0.20 / CTLE 6 dB / 增益 1.12 dex）：
   `x_{k+1} = clip(x_k − α_k · STEP_SPAN ⊙ dir, 搜索盒)`，`α_k = 0.05 × 0.97^k`。
   这样三组各以"箱宽的固定比例"前进 —— 旧版把 11 维梯度**整体**归一化，振幅大的 FFE 维独吞步长，
   增益维每步只走 ~0.004 dex，15 步几乎不动（等于"增益不可调"）。
4. **组梯度门控**：某组"走满整箱"的预测收益 < `1e-3 dex` 就冻结该组，不推无油水的维。
5. 投影到搜索盒（FFE ±0.10 / CTLE ±3 dB / 增益整箱）；`10^B(候选) > allowed_ber` 则步长折半重试（≤20 次）。
6. **边际收益门控**：Model A 预测的每步改善 < `0.01 log10` 即停。
7. 真实 BER_MLSE 逐步写入 trace，**只记账、不回传决策**。

### 4.1 步长选型（基线用例，真实协议 262144×3）

| α₀ | 最优步 | 真实改善（log10） | 末步相对种子 | 现象 |
| --- | --- | --- | --- | --- |
| 0.03 | 11 | −0.342 | −0.322 | 稳，但步数偏多 |
| **0.05（采用）** | 10 | **−0.342** | −0.342 | 稳、15 步内收敛 |
| 0.08 | 0 | −0.340 | −0.317 | 稳 |
| 0.15 | 2 | −0.335 | **+0.011** | 出现来回振荡（超出代理可用步长） |
| 0.25 | 0 | −0.326 | **+0.171** | 明显振荡，末步反而变差 |

### 4.2 基线用例的真值审计（为什么"平台期"是对的）

在基线用例上，把轨迹最优点与"按单旋钮实测最优值手工拼出来的点"对比（同为 262144×3）：

| 配置 | BER_MLSE | 相对种子 |
| --- | --- | --- |
| 种子 | `3.75e-04` | — |
| 只把增益调到 ×0.55（该旋钮单独最优） | `1.78e-04` | −0.322 |
| 只把 CTLE 调到 −3 dB（该旋钮单独最优） | `1.85e-04` | −0.306 |
| 增益 ×0.55 **且** CTLE −3 dB | `1.82e-04` | −0.314 |
| 只按实测梯度动 FFE（±0.05） | `2.40e-04` | −0.194 |
| 增益 ×0.55 + CTLE −1/−3 dB + FFE ±0.05（拼装） | `5.50e-04` / `8.78e-04` | **+0.17 / +0.37** |
| **DDPS 轨迹最优点（α₀=0.05，第 10 步）** | **`1.70e-04`** | **−0.342** |

结论：三个旋钮的作用**不可叠加**，手工拼装甚至会把 BER 推得更差；而梯度下降沿模型给出的联合方向走，
落在 **−0.342 dex（×2.2）**，优于任何"单旋钮最优组合"。同时轨迹里 **driver 增益倍率 ×1.00 → ×0.56**
（与 §2.1 实测的 ×0.5～×0.65 最优点一致），CTLE 反而略微上调 —— 因为增益降下来后需要把摆幅补回去，
单看 CTLE 自身的最优点（−3 dB）反而是错的。这正说明"三组自由度必须联合优化"。

## 5. 数据与评估协议

| 项 | 取值 |
| --- | --- |
| 训练环境 | **只有 `Base_IL10x10`**（Tx/Rx 插损 10 dB，无 CD/DGD） |
| 训练规模 | **2000 个 LHS 采样点 + 1 个精确种子点 = 2001 行真实 BER 评估** |
| 采样盒 | FFE ±0.10 / CTLE ±3.0 dB / Driver 增益倍率 ×0.30～×4.00（对数均匀） |
| 测试场景 | 15 个（其余 14 个场景**零样本**进入训练） |
| 评估协议 | **262144 符号/点 × 3 个仿真实例种子（42,43,44）取 log10 均值** |
| 长块复核 | 524288 符号 × 3 种子 |

块长精度实测（v4 链路，5 个独立实现）：

| 块长 | log10 BER 均值 | 跨种子标准差 | 漂移 | 能否分辨 ×2.05 的真实改善 |
| --- | --- | --- | --- | --- |
| 65536 | −3.035 | 0.061 | — | ❌ 符号翻转 |
| 131072 | −3.276 | 0.091 | −0.241 | ✅ |
| **262144（采用）** | −3.468 | 0.092 | −0.192 | ✅ |
| 524288 | −3.603 | 0.129 | −0.136 | ✅ |

结论与 v3 相同：绝对 BER 随块长系统性漂移，**不同块长不可比**；65536 太短会把真实收益淹没
（本轮实测：α₀=0.05 的轨迹在 262144×3 下是 −0.342 dex，在 65536 下只剩 −0.176 dex 且看不出后续差异）。

## 7. 已知边界

1. **拦截线只约束"预测恶化"**：若 Model B 沿下降方向把真实劣化误判为改善，百分比阈值再小也无效
   （v3 已用回放实验证明过这一点）。因此报告提供逐步 trace，便于事后核对每一步真实 BER。
2. **代理是局部模型**：FFE/CTLE 只在种子信任域内移动（±0.10 / ±3 dB）；增益允许走满整箱（数据覆盖整箱）。
   训练集只覆盖基线环境，因此**跨环境时模型给出的是"基线最优方向的外推"**，其有效性随环境偏离而下降
   （14 个测试场景的真实收益逐场景列在 `result/SUMMARY.md`，不作修饰）。
3. **方向命中率不是 100%**：种子点 11 轴实测命中率 0.82（加权 0.93），个别弱轴的符号仍会错，
   因此每步真实 BER 都必须记账，`best_step` 取真实最优而不是最后一步。
4. **增益最优值依赖摆幅标定**：换器件需重跑 `tools/calibrate_driver_gain.py` 并同步 `create_config.py`。
5. **CTLE 频响形状固定**：只优化双级直流增益，零极点比例不在搜索空间内。
6. **场景覆盖有限**：15 个场景覆盖 10/14/16/20 dB 插损组合与 CD/DGD/器件噪声，未穷举。
