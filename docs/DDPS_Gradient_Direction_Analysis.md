## 0. 结论摘要

1. **你的判断成立，而且比"只能在初始方向前进/后退"更严格**：重构前 secant 的下降方向在数学上
   **不会旋转**——组内方向（4 个 FFE 旁瓣之间的比例、gDC 与 gDC2 之间的比例）从第 1 步起被严格冻结；
   整条轨迹只活在"第 0 步方向的 3 个组权重"这 2 个自由度里。15 个用例、14 步、逐位核对：
   组内方向余弦 = ±1.000（精确等号级别）。
2. **实测有效自由度 = 1~1.75 / 7**（位移矩阵参与率中位 1.55；direct 1.02；每步链式 1.16）。
   三条轨迹都是"一条射线上的行进"，不是 7 维搜索。
3. **更狠的一条**：重构前每步位移与梯度**幅值无关**（被组内单位化约掉），只由三个组的**符号**决定。
   于是 15 个用例的归一化轨迹只有 3 种完全相同的型面——8 个信道条件迥异的用例走出**逐位相同**的路径。
   Model A 与割线的作用只剩"决定每步三个符号 + 何时把某组冻结"。
4. **割线在这个结构里退化成"步长估计器"**：因为位移方向 ∝ 梯度方向，秩-1 更新只能沿位移方向修正，
   于是它只能改梯度的**幅值与符号**，改不了方向。这正是 Barzilai–Borwein 那类"只定该走多远"的角色。
5. **换 CG 不能解决**（详见 §5）：CG 需要①每次迭代的**新梯度**②满足 Wolfe 的**线搜索**。
   重构前两者都没有——梯度方向不转，CG 的方向公式退化到同一条射线；线搜索也不存在（只有 Model B 可行性回溯）。
   把 CG 套在重构前的梯度估计上，等于给同一台发动机换个方向盘。
6. **真正的病灶是信息量**：每步只新增 1 个标量（ΔA 或 ΔBER）＋1 个自己选定的方向，用 1 个方程定 6 个分量。
   割线的"最小改动"更新恰好把改动全部投在"自己刚走过的方向"上，等于零新信息。
7. **一个必须先澄清的口径问题（影响方案选择）**：重构前的代码里探针是**发端模型算出来的**
   （`tx_channel_extract.extract_tx_features`：单位冲激过 Tx 链 + 固定序列测 drive RMS，不产生 BER、不碰在线链路）。
   也就是说，`_grad_a_chain(record_probe_ber=True)` 里每步 12~14 次真实 BER 评估是**记账**，
   不是算法需要。若部署上允许"用发端模型算探针"，那么 shape 维链式梯度每步可以**零真实 BER 重算**，
   方向立刻恢复可旋转——重构前"零过渡态"设计的收益需要重新界定。若部署上探针必须实测，则走 §7 的路线 B/C。
8. **顺带查出的两个现状问题**（与方向无关，但影响结论口径）：
   - **15/15 用例不是"收敛停"，而是"15 步预算用尽停"**（`stop_reason` 为空、末帧位移仍达信任箱的 5~6%）。
     原因是边际门控用的是 Model A 预测改善，而 A 在中后段**系统性乐观**（末帧 pred_a − real 中位 −0.63 dex，
     最差 −1.46 dex），门控永远不触发。direct（真实目标）则 15/15 都是 `marginal_gain` 自停，4~12 步结束。
   - **gain 维在 7/15 用例贴死 ±0.30 dex 信任域壁**（`du_gain` 正好 +0.300），而 gain 是唯一贡献主要增益的维度
     （离线 per-case RMS 扫描已经知道每个用例的最优 gain）。
   - **搜索盒的全局边界在所有 15 个用例里都是活的**：第 2 个 FFE 旁瓣 15/15 贴 `FFE_BOUND=−0.3`，
     gDC2（LF shelf）12/15 贴下界 0。更具体地，`seed_config_bad_1e4.json` 的 `best_pre_post[1] = −0.3147`
     **本身就超出全局边界 −0.3**，于是这一维的信任箱被 `_bounds` 搜成 `[−0.3, −0.2147]`（半宽、单侧），
     第 1 步就被截断——起点在这一维"生来就是贴边的"。

## 1. 重构前在线调优在算什么（代码级事实）

搜索空间 `x = [4 个 FFE 旁瓣, gDC, gDC2, u_gain]`（7 维，`ddps_optimizer.N_DIM`）。每步只做四件事：

| 环节 | 实现 | 备注 |
| --- | --- | --- |
| 方向 | `_secant_direction`（`ddps_optimizer.py:555`）：`direction[组] = (span⊙g)[组] / ‖(span⊙g)[组]‖`，各组**单位化**；`‖span⊙g‖<1e-3` 的组直接置 0（组门控） | 组=FFE / CTLE / gain 三块 |
| 步长 | `alpha = GD_LR · ALPHA_DECAY**step`（`:632`），即 0.05·0.97^k，**预定调度** | 不是线搜索 |
| "线搜索" | `_secant_line_search`（`:568`）：回溯 α，判据是 **Model B 预测 ≤ 红线**（可行性） | 目标函数（BER 或 A）**不参与** |
| 梯度 | 第 0 步：shape 维中心差分（12 个 ±ε 试探态）+ gain 维解析；此后 shape 维秩-1 割线（`:656-662`），gain 维解析现算（`:654`） | 割线方程剔除 gain 贡献 |
| 停止 | 组门控 / 无候选通过 B / 轨迹信任域 / 边际改善 `MIN_GAIN_DEX=0.01`（用 A 预测，`:669`）/ 步数用尽 | 见 §3.4 |

direct 版（`_stage2_descent_direct`，`:753`）同机制，只把目标换成真实 log10(BER)：第 0 步 7 维中心差分
（14 个真实评估），此后全 7 维 Broyden（`:806-811`），无 A/B 保护。

**关键结构（三条轨迹共有）**：位移方向与梯度同向（组归一化只是分块缩放），
即 `d_k = -α_k · D_k g_k`，`D_k` 是正对角阵。这是后面一切推导的前提。

## 2. 割线的本质：方向为什么在数学上不会转

### 2.1 推导

设割线更新（"good" Broyden 的最小改动形式）
`g_{k+1} = g_k + c_k d_k`，`c_k = (ΔA_k − g_kᵀd_k)/‖d_k‖²` ——
它把梯度改动**全部**投在位移方向 `d_k` 上（这正是"最小改动"的含义：满足割线方程且改动量最小）。

代入 `d_k = -α_k D_k g_k`（`D_k` 正对角）：

```
g_{k+1} = (I - α_k c_k D_k) g_k            ——  逐分量乘一个因子
```

`D_k` 的构造是 `D_k|第g组 = span_i² / ‖(span⊙g_k)[第g组]‖`，而 `span_i` **在组内是常数**
（FFE 全 0.2、CTLE 全 6.0、gain 0.6）。于是**组内每个分量乘的是同一个因子**：

```
g_{k+1,i} / g_{k,i} = 1 - α_k c_k D_k|组(i)   ——  组内比例严格不变
direction_{k+1}|组 = ± direction_k|组          ——  组内方向只能整体反号
```

**结论**：方向向量永远活在第 0 步方向张成的"3 组权重"族里（归一化后 2 个自由度）。
管你走多少步，`x` 只在一条射线上（外加组权重的正负号翻转）移动。这与"BER 只有升降"无关——
不是目标是一维的，而是**更新格式把梯度压进了一维**。

特例（最能说明本质）：若位移严格 ∝ −g（真实线搜索的最速下降），
则 `g_{k+1} = (I − cD)g_k` 与 `g_k` 同向，割线**只解出"沿这条射线该走多远"**，
方向维拿不到任何信息——正是 Barzilai–Borwein 类步长法的角色。

### 2.2 组门控是"自锁"的

`_secant_direction` 里，`‖span⊙g‖<1e-3` 的组被置 0 ⇒ 该组 `d_k=0` ⇒
割线更新 `g_{k+1}=g_k + c·d_k` 对该组的改动也是 0 ⇒ **该组永久冻结，割线自身永远无法复活它**
（只能靠外部信息：解析梯度、重算链式梯度、或明确的探索步）。这解释了 v8 之前
"纯割线 gain 维卡死"的现象：不是"弱方向被压塌"这么模糊，而是**门控清零 + 割线无法注入新方向**的结构性自锁。
重构前用解析梯度复活 gain 维，等价于承认"必须从外部注入方向信息"。

### 2.3 唯一能扰动方向的两件事

- **贴边截断**：`np.clip(x_new, tr_bounds)` 只截掉部分分量 ⇒ 实际位移不再 ∝ D g ⇒ 注入新方向。
- **组门控清零**：被清零的组位移为 0（方向被"删掉一维"而不是旋转，且不可逆——见 §2.2）。

信任箱占用实测（末帧 |x−seed| 半径 / 信任半径，15 用例）：
FFE 各维 ≤ 0.95、gDC ≤ 0.29、gDC2 ≤ 0.28 —— **都没顶满**；只有 gain 维到 1.00（secant/chain 各 7/15，direct 2/15）。
但**全局边界**是活的：第 2 个 FFE 旁瓣 15/15 贴 −0.3（且 seed 本身越界，见 §0 第 8 条），
gDC2 12/15 贴下界 0。一个 7 维搜索把一个维常年按死在边界上，本身就可疑。

### 2.4 最锋利的一条：每步位移与梯度**幅值无关**，只由 3 个符号决定

把 `_secant_direction` 的代换做完：组内方向 `u_g` 冻结 ⇒

```
位移[第g组] = -α_k · span ⊙ (span ⊙ g)_g / ‖(span ⊙ g)_g‖
            = -α_k · (span² ⊙ u_g) · ( |g_g| / ‖span ⊙ g‖_g )
            = -α_k · ‖span² ⊙ u_g‖ · u_g · sign(g_g)
```

**幅值 `|g_g|` 被约掉**。所以每步位移 = 预定 α 调度 × 固定的组内方向 × 三个组各自的**符号**。
换言之，整条 15 步轨迹 = **45 个符号位 + 边界截断**；Model A / 割线的全部作用只剩
"决定每组梯度在每一步的符号（以及是否低于门控被冻结）"。

**证据（这就是为什么它是真的）**：15 个用例的末帧信任箱占用比例（`|x−seed|/半径`，归一化坐标）
只有 **3 种完全相同的型面**，与环境无关：

| 归一化路径 | 末帧占用 (ffe0, ffe1, ffe2, ffe3, gdc, gdc2, ugain) | 命中的用例 |
| --- | --- | --- |
| P1 | 0.89, 0.83, 0.26, 0.28, 0.06, 0.28, 0.82 | Base_IL10x10、CD15ps、CD28ps、DGD2ps、DGD5ps、IL10x16、IL10x20_RxHeavy、HighNoise_IL10x10（8 个） |
| P2 | 0.87, 0.86, 0.26, 0.24, 0.14, 0.28, 1.00 | IL20x20、IL20x10_TxHeavy、Comb_IL20x20_CD15_DGD5、Comb_IL20x10_CD15_DGD5 |
| P3 | 0.74, 0.95, 0.31, 0.28, 0.29, 0.01, 1.00 | IL16x10、HighNoise_IL16x16 |

8 个不同信道（插损/色散/DGD/噪声全不同）走出**逐位相同**的归一化轨迹，
只能是"路径不含环境信息"——它们只是同一组三个符号的不同排列。
direct（真实 BER）没有这个现象：占用比例随用例连续变化（ffe0 0.28→0.98、gdc 0.07→0.65）。

## 4. 逐条回答你的疑问

| 疑问 | 核查结论 |
| --- | --- |
| 梯度下降方向凭什么合理？ | 方向合理性**只来自第 0 步**（一是 12 个 ±ε 试探的 shape 中心差分，二是 gain 解析梯度）。此后方向不再更新，整条路是同一条射线。direct 在 IL20x20 上 11 步到 −7.224（检测底），secant 15 步只到 −6.923，差别**全部**来自第 0 步方向的精度。 |
| 割线的本质是什么？ | 在"位移 ∝ 梯度"这个结构下，它是**沿已走过方向的步长/幅值估计器**（满足一个割线方程，最小改动），不是方向修正器。 |
| 只能沿初始方向前进/后退？ | **是**，而且更严格：组内方向精确冻结；能变的只有 3 个组权重（含反号），所以表现为"沿射线推进 / 回退 / 振荡"（CTLE 组每步反号 10/14 次即此）。 |
| 因为 BER 只有提升或下降？ | 不是。目标是不是标量无关紧要——7 维梯度本来可以转；是**更新格式**把它压成了一维。真正的约束是"每步只新增 1 个标量观测"。 |
| 不同维度该有不同调整方向吗？ | 是，物理上 FFE 形状、CTLE 峰化、驱动增益的最优方向各不相同；当时的算法只能给出"三组权重的比例"，组内比例被迫继承第 0 步。 |
| 该上 CG 吗？ | 先别（见 §5）。CG 是"方向已知但收敛慢（窄谷锯齿）"的解药；当时是"方向根本没被估计出来"。 |

## 5. 为什么 CG（以及 BFGS/动量）当时救不了

非线性 CG：`d_k = -g_k + β_k d_{k-1}`，`β_k`（FR/PR/HS）依赖**相邻两次的梯度**；
其共轭性来自二次函数 + **精确线搜索**的理论前提；实用中至少要 **strong Wolfe** 才能保证下降与收敛。

对照重构前：

1. **没有可用的新梯度**。把上面证明过的 `g_{k+1} = (I − cD)g_k`（组内方向不变）代入 CG：
   若 `d_{k-1}` 与 `g_{k-1}` 同向，则 `d_k ∝ −g_k` 仍然同向 ⇒ **CG 每一步都退回到同一条射线**，
   与重构前的最速下降完全等价，收益为 0。这不是实现问题，是数学结论。
2. **没有线搜索**。重构前只有"Model B 可行性回溯"；目标函数（无论是 A 还是真 BER）不进入步长决策。
   没有 Wolfe 条件，CG 的共轭性/下降性保证都不成立；而这个场景里唯一可做线搜索的目标是**代理**，
   那就等于用虚高的代理（§3.5）定步长，风险自负。
3. **维度不构成理由**。CG 的价值在"大 n、内存受限"；这里 n=7（shape 只有 6），
   真要用二阶信息，**全 BFGS（7×7）或直接在 Model A 的解析 Hessian 上做信赖域牛顿步**比 CG 更简单、更强。
   Model A 是二阶多项式 + 白盒解析梯度，Hessian 也是闭式的。
4. **噪声/代理误差放大了线搜索的难度**。BER 估计本身有实现噪声（0 错误检测底、单种子），
   加上代理跨环境偏差，CG 的经典假设（精确梯度 + 精确线搜索）都不满足。

**所以顺序应该反过来：先把"每步能不能拿到一个会转的梯度"解决，再谈用不用 CG/BFGS。**

## 6. 根因：每步的信息量

重构前每步得到的新信息 = **1 个标量**：
- 重构前：`ΔA = A(probe(x_{k+1})) − A(probe(x_k))`（Model A 预测的变化）；
- direct：`Δlog10BER`（真实）。

外加"这一步往哪走"（自己选的）。1 个方程要定 6 个 shape 分量的梯度 ⇒ **欠定**。
割线选"最小改动解"，而改动方向恰好是自己刚走过的方向 ⇒ 新信息为 0，方向被锁死。
这是 §2 推导的直观解释，也是"每步零试探态"这个约束的直接代价。

要打破它，只有两条路：**要么每步多拿信息（多一个方向的探针/斜率），要么把参数→探针的映射（∂probe/∂param）
用离线模型补上**。见下。

## 7. 怎么办：四条路线（按性价比）

> **已落地**：路线 A 与路线 B 都做了，并保留为可一键切换的两档——
> 路线 A = `--grad-mode full`（每步 7 个形状维各 ±ε，14 个微扰态/步）；
> 路线 B = `--grad-mode rotate`（第 0 步全量，此后每步轮转刷新 2 个维，4 个微扰态/步）。
> 原来的 secant 实现不再作为主推，仅保留为同预算对照档（`--grad-mode secant`）。
> 路线 C（离线标定 ∂probe/∂param）与路线 D（DFO 信赖域）未采用。

### 路线 0（零风险，先做）：把"哪一步停"和"gain 维在哪起步"做对

- 边际门控换成"A 预测改善 **且** 真实/几何边际"双判据（或按几何收敛判据自适应步数）。
  依据：15/15 都是预算用尽；后 9 步只贡献 7%；A 末帧乐观 0.63~1.46 dex。
- gain 维：离线 per-case RMS 扫描已有每个用例最优 gain（`result/per_case_target_rms.json`），
  直接用它做初值（或扩到足够覆盖的信任域），别让 7/15 用例卡在 ±0.30 dex 壁上"搜一个已知答案"。
- 第 0 步的 12 个试探态用在刀刃上：按"预测收益"选维、`eps` 自适应（当时 0.01/0.1 固定分档）。
- 修起点越界：`pick_seed_config.py` 选点时没有校验全局边界，
  `best_pre_post[1] = −0.3147` 越过 `FFE_BOUND = 0.3`，导致这一维的信任箱退化成单侧半宽（§0 第 8 条）。
  起点必须落在搜索盒内。

### 路线 A（推荐主线，改动最小、收益最大）：每步重算 shape 维链式梯度

- 事实依据：`_probe_features`（`ddps_optimizer.py:211`）→ `extract_tx_features`
  只跑 **Tx 前端模型**（单位冲激 + 固定序列测 RMS），**不产生 BER、不扰动在线链路**；
  `_grad_a_chain` 里的真实 BER 评估全在 `if record_probe_ber:` 里（`:312-328`），是记账。
- 因此把 `:656-662` 的割线更新换回 `_grad_a_chain(dims=shape)`（`record_probe_ber=False`），
  方向**每步都可旋转**，而真实 BER 评估次数与重构前相同（每步 1 次落点评估）。
- 代价口径要重写：v7.3 链式"每步 14 次评估"是记账开销，不是算法成本；重构前"8× 评估量减少"的说法需要重新界定。
- **成本实测**（本机 Python 侧计时）：一次 shape 探针计算 = **5.6 ms**，12 次 = **0.068 s**；
  对照 2^22 全链路单次评估 ~30 s（C++/WSL）——即"每步重算 7 维链式梯度"的额外开销约为**一次真实评估的 0.2%**。
- 成立的前提（**需要你确认**）：部署上允许用发端模型算探针，而不是必须实测扰动后的探针。

### 路线 B（不动部署假设）：轮转坐标刷新

若探针必须实测：**每步只对一个 shape 维做探针刷新**（选预测收益最大的那一维，单边或双边差分），
其余维沿用上一次的梯度，6 步刷满一轮。摊销扰动 = 每步 1 个过渡态（与第 0 步 12 个态同量级、但摊开），
方向恢复可旋转。实现上是"半链式"，改 `_stage2_descent_secant` 的内部循环即可。

### 路线 C（白盒、零在线扰动）：离线标定 ∂probe/∂param

Tx 链是 LTI：∂probe/∂FFE 抽头是解析线性映射；∂probe/∂gDC、∂probe/∂gDC2 用离线 TX 模型一次性算出。
在线每步只算 ∂A/∂probe（解析）+ 雅可比 ⇒ 拿到 7 维链式梯度，**零在线扰动**。
这与项目"白盒"理念最一致，代价是需要维护一份 Tx 前端口径的雅可比（参数漂移时更新）。

### 路线 D（若坚持"每步 1 个标量"）：换成正经的 DFO 信赖域

- 去掉"组内单位归一化"（它正是冻结组内比例的元凶），
- 用累积落点拟合**二次插值模型**（`n=7` 时约 28 个点即可定二次模型，15 步内做局部模型 + 正则化），
- 步长由模型给出（信赖域），而不是固定 0.05·0.97^k。
这是工作量最大、但理论上最贴合"1 观测/步"约束的方案；参考 DFO 的插值/信赖域思路
（Conn–Scheinberg–Vicente 的模型型 DFO；以及欠定二次插值模型的工作，如
[SIAM J. Optim. "A Derivative-Free Method Using a New Underdetermined Quadratic Interpolation Model"](https://epubs.siam.org/doi/abs/10.1137/23M1582023)）。

### 若终要走 CG/BFGS

只有在路线 A/B/C 之一落地、每步有"会转的梯度"之后才有意义。
届时建议顺序：**先加真线搜索（在代理上做 Armijo/Wolfe，步长由模型给）→ 再试 BFGS/L-BFGS（n=7，无需 CG 的内存优势）
→ CG 只在需要省内存时考虑**。三者都必须自己实现（项目"无第三方包"约束）；
7×7 BFGS 与 CG 的 FR/PR 更新都只有十几行。

## 8. 建议的验证实验（合规口径）

AGENTS.md 硬规则：比对只在 2^18 小点数低 SNR 做，全量只走 C++。

1. **Python 2^18 低 SNR（单种子 42、次优起点、15 步）**，四方对照：
   - 重构前 secant（基线）；
   - 路线 A：每步重算 shape 链式梯度（`record_probe_ber=False`）+ gain 解析；
   - 路线 B：轮转坐标刷新；
   - direct（已有）。
   指标：最终 log10 BER、收敛步数、真实 BER 评估次数、逐步方向转角 cos(d_k,d_{k-1})、参与率。
2. **C++ 2^22 只跑 2~3 个最难用例**（IL20x20、Comb_IL20x20_CD15_DGD5、HighNoise_IL16x16）复核。
3. 判据：若路线 A/B 在同一预算内最终 BER 明显优于 secant（或同 BER 但收敛步数显著更少）⇒ 进现役；
   否则保留 secant 但按路线 0 修停止判据与 gain 起点。
